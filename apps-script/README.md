# Google 쪽 설정 순서

Apps Script 웹 앱은 두 개이고 서로 다른 프로젝트로 만듭니다.

| 웹 앱 | 코드 | 하는 일 | 액세스 권한 |
| --- | --- | --- | --- |
| 입구 | `gate/Code.gs` | 학교 계정을 확인하고 열쇠를 붙여 웹앱으로 넘김 | 학교 도메인 내 모든 사용자 |
| 결과 수신 | `results/Code.gs` (뒤 단계에서 만듦) | 학생 결과를 반별 시트에 적음 | 뒤 단계에서 정리 |

## 입구 배포

먼저 할 일: 교사 컴퓨터에서 `node tools/lock.mjs`를 한 번 실행합니다. `private/vault.key`가 생기고 `content/`에 잠긴 파일이 만들어집니다. 잠긴 파일을 커밋·푸시해 GitHub Pages에 올립니다.

1. 학교 계정으로 [script.google.com](https://script.google.com)을 열고 **새 프로젝트**를 만듭니다. 이름은 자유입니다(예: `L8 입구`).
2. 편집기의 `Code.gs` 내용을 모두 지우고 `apps-script/gate/Code.gs`를 통째로 붙여 넣은 뒤 저장합니다.
3. 왼쪽 톱니바퀴 **프로젝트 설정** → 맨 아래 **스크립트 속성** → **스크립트 속성 추가**로 두 개를 넣습니다.

   | 속성 | 값 |
   | --- | --- |
   | `KEY` | `private/vault.key` 파일을 메모장으로 열어 한 줄(43자)을 그대로 복사 |
   | `APP_URL` | 웹앱 주소. 예: `https://<계정>.github.io/time-travel/` (끝에 `/`) |

4. 오른쪽 위 **배포** → **새 배포** → 톱니바퀴에서 유형 **웹 앱**을 고릅니다.
   - 실행: **나**
   - 액세스 권한: **(학교 이름) 내 모든 사용자**
5. **배포**를 누르고, 나오는 **웹 앱 URL**(…`/exec`)을 복사합니다. 이것이 학생에게 알릴 **입구 주소**입니다. `data/config.js`의 입구 주소 칸에도 적어 둡니다(교사 안내용).

## 배포한 뒤 확인

- [ ] 교사 계정으로 입구 주소를 열면 "신원 확인 완료."와 "입장" 단추가 보인다.
- [ ] "입장"을 누르면 웹앱의 접속 화면으로 가고, 주소창에 `#k=`가 남아 있지 않다.
- [ ] **학생 계정**으로 로그인한 크롬북에서 입구가 열린다. 교사 계정과 학생 계정의 도메인이 다르면 여기서 막힐 수 있습니다.
- [ ] 학교 밖 계정(개인 Gmail)이나 로그아웃한 창에서는 Google의 로그인·접근 거부 화면이 나온다.
- [ ] 웹앱 주소를 입구 없이 바로 열면 "접속 권한이 없다. 입구 주소로 다시 접속하라."가 나온다. (접속 화면을 만든 뒤 확인)

"설정 필요: 스크립트 속성 KEY, APP_URL"이 보이면 3번의 속성 이름이나 값이 틀린 것입니다. `KEY`는 43자, `APP_URL`은 `https://`로 시작해야 합니다.

### "입장" 뒤에 "접속 권한이 없다"가 나올 때: 열쇠 지문 맞춰 보기

입구에 넣은 `KEY`가 `private/vault.key`와 다르면 이렇게 됩니다. 열쇠를 화면에 꺼내지 않고 '지문'(열쇠를 바꾼 8자)으로 견줍니다.

1. 교사 컴퓨터에서 `node tools/key-check.mjs`를 실행합니다. `열쇠 지문 ……` 8자가 나옵니다.
2. Apps Script 편집기 위쪽의 함수 고르는 칸에서 `checkKey`를 고르고 **실행**합니다. 처음이면 권한 허용 창이 나옵니다.
3. 아래 **실행 로그**의 `열쇠 지문`이 1번과 같은지 봅니다.
   - 다르면: 스크립트 속성 `KEY`를 지우고 `private/vault.key`를 메모장으로 열어 한 줄 전체를 다시 붙여 넣습니다(Ctrl+A → Ctrl+C). 다시 배포하지 않아도 바로 반영됩니다.
   - 같으면: 로그의 `APP_URL`이 Pages 주소와 같은지 봅니다. 그래도 안 되면 배포 관리에서 **새 버전**으로 다시 배포합니다.

## 고칠 때

- **코드를 고쳤을 때:** **배포** → **배포 관리** → 연필 → 버전 **새 버전** → 배포. 주소는 그대로입니다.
- **열쇠를 바꿀 때:** `private/vault.key`를 지우고 `node tools/lock.mjs`를 다시 실행 → `content/`를 커밋·푸시 → 스크립트 속성 `KEY`를 새 값으로 바꿉니다. 속성만 바꾸면 되고 다시 배포하지 않아도 됩니다. 학생 기기에 남은 옛 열쇠는 풀리지 않게 되어, 입구 주소로 다시 들어와야 합니다.
- **단원이 끝난 뒤 닫을 때:** **배포 관리**에서 입구 배포를 **보관처리**합니다. 복습용으로 남기려면 입구는 그대로 두고 `data/config.js`의 결과 전송 주소만 비웁니다.

## 지킬 것

- 열쇠는 `private/vault.key`와 입구의 스크립트 속성 두 곳에만 둡니다. 저장소, 코드, 메신저, 문서에 붙여 넣지 않습니다.
- 학생에게는 입구 주소만 알립니다. 웹앱 주소(`github.io`)는 알리지 않습니다.
- 입구는 누가 열었는지 적지 않습니다. 학생 정보는 결과 수신 쪽의 반·번호뿐입니다.
