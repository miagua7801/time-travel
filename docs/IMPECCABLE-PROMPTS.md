# 노트북 Claude Code에서 돌릴 impeccable 프롬프트

준비: 저장소 폴더 맨 위에 `PRODUCT.md`, `docs/`에 `AUDIT-2026-11-25.md`를 넣는다. `private/`와 열쇠가 있는 노트북에서, 모델은 Opus로 한다.
순서: ① harden → 보고 확인 → 커밋 → ② polish → 보고 확인 → 커밋. 한 번에 하나씩.

---

## ① harden

```
/impeccable harden

대상: 이 저장소의 학생 웹앱 전체 (S0~S11).
먼저 CLAUDE.md, PRODUCT.md, docs/ARCHITECTURE.md, docs/AUDIT-2026-11-25.md를 읽어.
감사 보고서의 P1·P2 항목을 이 순서로 처리해:
1. 포커스 테두리 대비: 흰 바탕 화면에서 3:1 이상 (검은 바탕은 지금 색 유지). 색은 :root 토큰으로.
2. js/player.js: 장면 음성을 파일마다 따로 풀고, 실패한 덩어리만 건너뛰게.
3. 소리를 받지 못한 장면: 다시 받는 방법. 새 문구가 필요하면 만들지 말고 장면과 초안만 보고해.
4. 화면 크기: tools/shot.mjs로 1280×720, 1366×768(100%·125% 확대), 1920×1080에서 S0~S11을 캡처하고, 잘리거나 겹치는 곳만 고쳐. 디자인은 바꾸지 마.
5. 2차시 판단(기기 날짜): 코드는 고치지 말고, 같은 날 1·2차시를 하는 경우의 문제와 선택지를 보고만 해.
그 밖에 harden 점검(빈 상태, 긴 반·번호, 빠른 연속 누르기, 오프라인, 저장 막힘)에서 찾은 것은 고치기 전에 목록으로 먼저 보고해.

지킬 것: CLAUDE.md 규칙 전부. 특히 private/와 열쇠는 읽기만, 화면 문구는 data/copy.js에 있는 것만, 장식 효과 금지, 효과 1초 이하.
끝나면 CLAUDE.md의 보고 형식으로: 바꾼 파일, 실행한 검사와 결과(캡처 경로), 직접 보지 못한 것, 교사가 볼 것, 새로 필요한 문구. 커밋은 내가 확인한 뒤에.
```

**보고에서 볼 것**
- 키보드 Tab으로 흰 화면(S3, S4, S5)을 돌 때 주황 테두리가 잘 보이는지 직접 확인.
- '새로 필요한 문구'가 있으면 Opus 기획 대화로 가져와 정한다.
- 캡처에서 125% 확대 화면이 잘리지 않는지.

## ② polish

```
/impeccable polish

대상: 학생이 가장 오래 머무는 화면부터 — S5 장면(본문·묻기 칸), S4 길 지도, S10 수료증, S11 되감기·단서 수첩, 그다음 나머지.
CLAUDE.md, PRODUCT.md, docs/AUDIT-2026-11-25.md를 기준으로 해.
할 것: 정렬, 간격, 글자 크기 위계, 상태 표시(지금·마침·잠김, 재생 중, 고른 선지), 포커스 순서, 1366×768에서의 균형. 감사 보고서 P3(16px 보조 글자)는 바꿀지 말지 근거와 함께 제안만.
하지 말 것: 새 효과·장식(그림자, 그라데이션, 흔들기 등), 새 문구, 문구 말투 바꾸기, 화면 구조 바꾸기, 교과서 내용 손대기.
tools/shot.mjs로 고치기 전·후를 1366×768로 캡처해 같은 화면끼리 비교할 수 있게 tools/shots/에 남겨.
끝나면 CLAUDE.md의 보고 형식으로 보고. 커밋은 내가 확인한 뒤에.
```

**보고에서 볼 것**
- 고치기 전·후 캡처를 나란히 보고, 학생이 읽기에 더 편해졌는지.
- 문구나 화면 순서가 바뀌지 않았는지.
