# ARCHITECTURE — Lesson 8 읽기 중 활동 웹앱

1단계 설계 문서. 화면의 기준은 `private/스토리보드.md`(2026-11-16에 다시 내보낸 판)이고, 이 문서는 그것을 코드로 옮길 때의 구조를 정한다.
이 문서에는 교과서 문장과 장면 5 암호를 쓰지 않는다. 문장은 학습지 D 번호(`D21`처럼)와 음성 파일 이름(`R_3_11`)으로만 가리킨다.
결정의 근거는 7장 결정 기록에 있다. 답을 기다리는 점은 없다.

- `assets/audio/`는 쓰지 않는다. 음성은 모두 `content/`의 잠긴 묶음으로만 올린다.

- `data/copy.js`와 `data/scenes.js`에는 영어 본문 문장을 넣지 않는다. 문구 안에 본문 문장이 필요한 곳(장면 2 ★ 도전의 인용, S6의 큰 글씨)은 `{quote}` 자리만 두고 실행 중에 잠긴 데이터에서 채운다.

## 2. 데이터 형식

### 2.1 평문 (private/)

| 파일 | 내용 | 상태 |
| --- | --- | --- |
| `audio_map.json` | 음성–본문 짝. `story` 111개: `order`(1~111 전체 순번), `file`, `page`, `scene`, `worksheet_line`(학습지 D 번호), `speaker`, `text`, `seconds`. `repeated_sentences` 10개는 쓰지 않음 | 교사 확인 완료 |
| `word_gloss.csv` | 단어 뜻 30줄: `first_scene`(처음 나오는 장면), `word`, `meaning_ko` | 교사 확인 중 |
| `content/extras.json` | 아래 모양. 교과서 문장이 들어가므로 private에만 둠 | 다음 단계에서 만듦 |

```jsonc
// private/content/extras.json (모양만)
{
  "keyLines": [6, 4, 13, 18, 19, 21, 24, 26, 29, 40, 45, 47, 50, 66, 69, 74],   // 핵심 문장 16개의 D 번호
  "vocabForms": { "목록의 낱말": ["본문에 실제로 나온 꼴"] },      // 꼴이 달라 그대로는 못 찾는 낱말만 (지금 2개)
  "checks": {
    "c1": { "options": [ { "en": "…", "ko": "…" }, … 3개 ], "answer": 1, "evidence": 4 },
    "c2": { …, "evidence": 19 }, "c4": { …, "evidence": 40 }, "c5": { …, "evidence": 50 }, "c6": { …, "evidence": 74 }
  },
  "cards": { "1": { "back": "…" }, … "6": { "back": "…" } },      // 뒷면 문장. D 줄의 일부일 수 있어 글자로 둠
  "sign": { "wrong": "…", "locked": ["…"], "words": [ { "wrong": "…", "options": ["…", "…"], "answer": 1 } … 7개 ] },
  "quotes": { "star2": 21, "s6": ["R_6_9", "R_6_10"] }
}
```

- 핵심 문장 16개는 기획안 4장 표의 문장을 `audio_map.json`에서 찾은 D 번호다 (장면 1: 6·4·13, 장면 2: 18·19·21, 장면 3: 24·26, 장면 4: 29·40·45, 장면 5: 47·50, 장면 6: 66·69·74).
- 확인 문제는 스토리보드 4·5장의 문항 그대로다. 영어 선지도 근거 문장과 함께 잠근다.
- 단어 뜻 30개 가운데 28개는 목록의 꼴 그대로(또는 끝에 -s, -ed, -ing가 붙은 꼴로) 그 장면 본문에서 찾을 수 있다. 꼴이 바뀌거나 사이에 말이 끼는 2개만 `vocabForms`에 본문 속 꼴을 적는다.

### 2.2 잠긴 뒤 앱이 받는 모양 (story.bin을 풀면)

```jsonc
{
  "v": 1,
  "scenes": {
    "1": {
      "page": 139,
      "lines": [                         // 한 줄 = 학습지 D 번호 하나 = 화면의 문장 한 덩어리
        { "d": 1, "title": true, "key": false, "chunks": [ { "id": "R_1_1", "who": "narrator", "text": "…", "sec": 3.13 } ] },
        { "d": 2, "key": false, "chunks": [ { "id": "R_1_2", "who": "narrator", "text": "…", "sec": 3.63 } ] }
      ],
      "vocab": [ { "word": "…", "meaning": "…", "spans": [ { "d": 4, "c": 0, "s": 37, "e": 46 } ] } ]   // 줄 d의 c번째 덩어리 글에서 s~e 글자
    }
  },
  "checks": { … }, "cards": { … }, "sign": { … },
  "quotes": { "star2": "…", "s6": "…" }
}
```

| 대상 | 단위와 규칙 |
| --- | --- |
| 장면 | 6개. 줄은 `order` 순. 줄 수는 장면 1부터 13·8·7·17·7·15, 합 67줄. D 번호는 1~52, 60~74 (53~59는 원래 없음) |
| 제목 줄 | D1(`R_1_1`). 장면 1 본문 맨 위에 크게 보이고, 이어 듣기에 들어가며, 누르면 재생 |
| 음성 덩어리 | 111개. `id`는 출판사 파일 이름 그대로. 한 줄에 1~4개. `who`는 narrator·parker·eckels·travis |
| 핵심 문장 | 줄 단위 `key: true`. 한 줄이 덩어리 여럿이면 줄 전체에 옆줄 |
| 단어 뜻 | 30개. 낱말이 실린 장면(`first_scene`) 안에서 나올 때마다 모두 점선 밑줄. 다른 장면에서는 표시하지 않음 |
| 확인 문제 | 5개: `c1 c2 c4 c5 c6` (숫자는 장면). 선지 3개는 적힌 순서 그대로(짧은 것부터), 섞지 않음. `evidence`는 첫 오답 때 밑줄 칠 D 번호 |
| 카드 | 6장. 그림은 `assets/img/cards/card_*.webp`(잠그지 않음), 뒷면 문장만 잠금 |
| 간판 | 틀린 간판 글, 누를 수 없는 낱말 3개, 고칠 낱말 7개와 선지 2개씩. 선지 좌우는 열 때마다 섞음 |

## 3. 화면 흐름과 상태

### 3.1 전체 흐름

```
입구(Apps Script) "입장" ─열쇠→ S0 접속 ─→ S1 영상 ─→ S2 제목·여행 선택 ─→ S3 반·번호 ─→ S4 길 지도
S4 ⇄ S5-1 … S5-4 ─→ S6 To be continued (1차시 끝)
S0 재접속 ─→ S7 지난 이야기 ─→ S8 암호 ─→ S5-5 ⇄ S4 ⇄ S5-6 ─→ S9 간판 ─→ S10 수료증 ⇄ S11 되감기
S8로 가는 다른 길: S3 "장면 5부터" · S4의 장면 5 칸(장면 4를 마친 뒤) · S6 "이어서 출발"(2차시)
```

화면은 주소를 바꾸지 않고 `go(이름, 값)`으로 바꾼다. 뒤로 가기 단추에 기대지 않는다. 화면을 바꿀 때마다 재생 중인 소리를 멈추고, 그 화면의 첫 문구로 포커스를 옮긴다.

**2차시 판단:** S3에서 보고한 날짜(기기의 날짜)를 저장해 두고, 오늘이 그날과 다르면 2차시로 본다.

### 3.3 "이어서 출발"이 가는 곳

스토리보드 S0의 규칙에 결정 28(도중에 끊긴 S6·S9)를 더한 것이다. 위에서부터 맞는 첫 줄로 간다.

| 반·번호가 없음 | S2 (영상을 못 봤으면 S1) |
| 엔딩을 봄 | S4 |
| 암호를 풀었고 장면 6을 마쳤는데 엔딩 전 | S9 |

| 장면 4를 마쳤는데 S6을 끝까지 못 봄 | S6 |
| 장면 1~4를 마쳤고 2차시임 (오늘이 S3에서 보고한 날과 다른 날) | S7 |
| 그 밖 | S4 (하던 장면이 강조). 장면 1~4를 마친 같은 날의 재접속도 여기 |

### 3.4 장면 화면(S5)

**배치 (1366×768, 페이지는 스크롤하지 않음)**

| 자리 | 내용 |
| --- | --- |
| 맨 위 띠 | 왼쪽에 길 지도 칸 6개(지금 장면 강조), 오른쪽에 장면 이름 |
| 가운데 왼쪽 약 1/3 | 장면 그림. 장면 1·6은 모서리에 TV 단추. 도입 문구가 그림 위에 3초 |
| 가운데 오른쪽 약 2/3 | 본문 칸. 위쪽에 "이어 듣기", 문장마다 한 줄, 핵심 문장은 왼쪽 파란 옆줄, 오른쪽 아래에 "다 읽었다". 이 칸 안에서만 스크롤 |
| 아래 전체 너비 | 묻기 칸. 왼쪽에 Travis, 그 옆에 한국어 발문, 아래에 영어 선지 3개를 가로로, 맨 오른쪽에 "뜻 보기". "다 읽었다"를 누른 뒤에 나타나고, 그때도 그림과 본문은 보임 |
| 맨 아래 | 저작권 문구 (모든 화면 공통) |

치수는 S5를 만드는 단계에서 캡처로 확정한다.

**단계**

| 단계 | 내용 | 다음으로 가는 조건 |
| --- | --- | --- |
| open | Travis 한 줄(장면 3·5·6: 첫 여행은 예측 되돌려주기, 두 번째 여행은 단서를 찾으며 읽으라는 말) → 내레이션 도입 3초 | 자동 |
| read | 본문 읽기. 이어 듣기·문장 듣기·단어 뜻·TV 단추 | 본문 칸의 마지막 줄이 보이면 "다 읽었다"가 켜짐 |
| ask[i] | 묻기 1~2번(두 번째 여행의 장면 4는 3번). 본문은 계속 보임 | 답하면 다음 묻기 |
| done | Travis 요약 → 카드 획득 → "다음 장면" (+ "★ 도전") | 단추 |

- 본문이 한 화면에 다 들어오는 장면은 "다 읽었다"가 바로 켜진다.
- 확인 문제: 선지를 누르면 바로 판정. 첫 오답이면 근거 줄에 밑줄을 긋고 선지를 잠근 뒤 "다시 고르기". 둘째 오답이면 정답 선지를 표시하고 넘어간다. 기록은 첫 시도만 정답으로 센다.
- 선지는 숫자 키 1~3으로도 고른다. 정답·오답은 색과 함께 기호(✓ ✕)와 `role="status"` 문구로 알린다.
- 예측과 관찰 일지는 한 번 고르면 바꿀 수 없다. 관찰 일지를 고른 뒤에는 ①②③ 모두 `flash` 줄이 잠깐 빛나고, 맞다 틀리다는 말하지 않는다.
- 재생 표시는 줄(학습지 번호) 단위다. 재생 중인 줄을 색과 ▶ 기호로 표시한다.
- 묻기 도중 새로고침하면 그 장면의 read 단계로 돌아오고, 이미 답한 묻기는 다시 묻지 않는다.
- 다시 보기(S4에서 마친 장면을 누름): read 단계만. 묻기 자리에는 내가 고른 답을 보여 주고 고칠 수 없다. "★ 도전"은 남아서 쓴 답을 고칠 수 있고, 낼 때마다 결과 시트로 보낸다.
- 소리 묶음을 못 받으면 듣기 단추를 흐리게 하고 읽기는 그대로 진행한다.

### 3.5 "장면 5부터"로 온 학생

기록이 사라진 기기로 2차시에 들어온 학생이다. S3에서 보고한 뒤 "장면 5부터"를 누르면 `flags.from5`를 세우고 S8로 간다.

- 장면 1~4를 마친 것으로 보고 길 지도에 카드 앞면을 보인다.
- 장면 1~4 다시 보기에는 고른 답이 표시되지 않는다.
- 기록이 없는 예측·관찰 칸은 지난 이야기와 수료증에서 숨긴다. 장면 5를 열 때의 예측 되돌려주기도 나오지 않는다.
- 결과 시트의 1차시 칸은 건드리지 않는다 (4.3).

### 3.6 '두 번째 여행'에서 달라지는 점

`trip`이 2일 때만 바뀌는 곳이다. 본문, 확인 문제, 관찰 일지, 카드, 간판, 암호는 같다.

| 곳 | 첫 여행 (`trip: 1`) | 두 번째 여행 (`trip: 2`) |
| --- | --- | --- |
| S3 보고 뒤 | 임무 문구 | 임무 문구 + 추가 임무 한 줄 |
| S5 본문 | ☆ 없음 | 줄 끝에 ☆. 누르면 단서 수첩(`notes`)에 담김, 한도는 설정값 |
| 장면 3·5·6이 열릴 때 | 예측 되돌려주기 | 단서를 찾으며 읽으라는 Travis 한 줄 |
| `p1`(장면 2)·`p3`(장면 5) | 한국어 선택지 3개 | 그 장면 본문에서 줄 하나를 고르거나 "없다" → 이유 한 줄(비워도 됨) |
| `p2` | S6에서 선택지 3개 | 장면 4 묻기 칸 끝에서 장면 4의 줄 하나 고르기. S6에서는 예측 단계를 건너뜀 |
| 고른 줄의 저장 | — | `picks`에 따로 저장. 단서 수첩 5칸에 세지 않음 |
| S7 | 내 예측 ①② | 예측 자리에서 고른 줄 ①② |
| S10 | 내 예측과 실제로 일어난 일 | 예측 자리에서 고른 문장 3개 |
| S4 | 단서 수첩은 되감기 뒤에 보임 | 단서 수첩이 처음부터 보임 |
| S11 | 수첩이 비어 있음 | 읽으며 담은 단서가 들어 있고 더하거나 뺄 수 있음 |
| 결과 시트 | 예측 열에 고른 선택지 | 예측 열에 고른 줄과 이유 |

"여행 다시 고르기"(S4, 장면 1을 마치기 전): S2로 돌아가 다시 고른다. 반·번호는 채워진 채 S3을 다시 거치고, 장면 1에서 담은 단서는 비운다.

## 4. 기기 저장과 결과 전송

### 4.1 기기 저장 (localStorage)

모든 읽기·쓰기는 try/catch로 감싸고 메모리 사본을 함께 둔다. 저장이 막혀도 진행은 계속된다.

| 키 | 내용 |
| --- | --- |
| `tt8:key` | 열쇠. "내 기록이 아니다"로 지우지 않음 |
| `tt8:v2:rec` | 이 기기의 기록 하나 (한 기기 = 한 학생) |
| `tt8:v2:out` | 아직 보내지 못한 결과. 반·번호별 최신 한 건씩 |

```jsonc
// tt8:v2:rec
{
  "v": 2,
  "cls": "2-3", "num": 14, "trip": 1,
  "day": "2026-11-20",                              // S3에서 보고한 날짜. 2차시 판단
  "flags": { "video": true, "s6": false, "unlocked": false, "ended": false, "reported": false, "from5": false },
  "done": [1, 2],                                   // 마친 장면
  "checks": { "c1": { "first": true, "pick": 1 }, "c2": { "first": false, "pick": 0 } },   // 첫 시도 정답 여부와 첫 시도에 고른 선지
  "predict": { "p1": "b" },                         // 첫 여행: 선택지 a·b·c
  "picks": { "p1": { "d": 21, "why": "…" } },       // 두 번째 여행: 고른 줄(없다는 null)과 이유
  "mood": { "m1": "excited" },
  "star": { "s1": "…" },                            // ★ 도전에 쓴 답
  "sign": { "fixed": [0, 3], "wrong": 1 },          // 고친 낱말 순번, 오답 횟수
  "notes": [ { "d": 21, "memo": "…" } ],            // 단서 수첩. 최대 설정값
  "t": "2026-11-20T01:23:45.000Z"
}
```

- 기기에는 본문 문장을 저장하지 않는다. 단서와 고른 줄은 D 번호로만 둔다.
- 이름·이메일·기기 정보는 저장하지 않는다.
- 이전 판(`tt8:v1:`)의 기록은 읽지 않는다.

### 4.2 결과 전송

- 주소: `config.js`의 결과 전송 주소. 비어 있으면 아무것도 보내지 않는다.
- 방식: `POST`, 본문은 JSON 글자(`text/plain`). 응답 `ok`를 받으면 대기열에서 지운다.
- 실패: 화면에 알리지 않는다. `tt8:v2:out`에 남기고 다음 전송 때 함께 보낸다.
- 보내는 것은 그 학생의 지금까지 값 가운데 값이 있는 칸 전부다. 그래서 대기열에는 학생마다 최신 한 건만 있으면 된다.

```jsonc
{
  "v": 2, "cls": "2-3", "num": 14,
  "fields": {                      // 값이 있는 칸만 넣는다
    "trip": "첫 여행", "done": 4,
    "c1": "O", "c2": "X1", "c4": "O",          // X 뒤 숫자는 첫 시도에 고른 선지 번호
    "p1": "…", "p2": "…",                       // 고른 선택지 글. 두 번째 여행은 "D21 문장 / 이유" 또는 "없다"
    "m1": "excited", "m2": "terrified",
    "s1": "…", "s2": "…",
    "signWrong": 2, "ended": "O",
    "n1": "2 · D21 문장 / 메모", "n2": "…"     // 단서 수첩 최대 5칸. 장면 번호, 문장, 메모
  }
}
```

| 보내는 때 | 새로 채워지는 칸 |
| --- | --- |
| 장면을 마칠 때마다 | 여행, 마친 장면 수, 확인, 예측, 관찰 |
| S6 | 예측 ②, ★ 답 |
| ★ 도전을 낼 때마다 (고쳐 낼 때 포함) | ★ 답 |
| S10 | 간판 오답 횟수, 엔딩 |
| S11 "보고" (다시 보고해도 보냄) | 단서 1~5 |

### 4.3 결과 시트 (apps-script/results/Code.gs)

- 반별 시트(이름 `2-1` ~ `2-6`). 한 학생이 한 줄, 번호 순으로 정렬.
- 열: 번호 · 여행 · 마친 장면 · 확인1 · 확인2 · 확인4 · 확인5 · 확인6 · 예측① · 예측② · 예측③ · 관찰① · 관찰② · 관찰③ · ★1 · ★2 · ★5 · ★6 · 간판 오답 · 엔딩 · 단서1 ~ 단서5 · 받은 시각
- **덮어쓰기는 칸 단위다.** 같은 반·번호의 줄을 찾아, 이번에 온 칸만 바꾸고 오지 않은 칸은 그대로 둔다. 기록이 사라진 기기에서 보내도 1차시 칸이 지워지지 않는다.
- 받지 않는 것: 반 목록에 없는 반, 1~40 밖의 번호. 글 길이는 칸마다 자르고, `= + - @`로 시작하는 글은 수식으로 실행되지 않게 앞에 `'`를 붙인다.
- 동시에 여러 명이 보내도 줄이 엉키지 않게 잠금(LockService)을 건다.
- 시트는 교사의 Google 드라이브에만 있다. 단서 칸에는 본문 문장이 들어가므로 시트를 공개로 공유하지 않는다.

| 값 | 기본 | 비고 |
| --- | --- | --- |
| 반 목록 | 2-1 ~ 2-6 | 결과 수신 쪽 목록과 같게 |
| 번호 범위 | 1 ~ 40 |  |

**장면 5 암호:** 반마다 다른 낱말이고, 낱말은 스토리보드 S8 표에만 있다. `config.js`에는 `SHA-256("tt8:" + 반 + ":" + 대문자로 바꾼 암호)`의 16진수 글자를 반별로 둔다. S8은 입력을 대문자로 바꾸어 같은 식으로 계산해 그 반의 값과 견준다. 교사는 `node tools/code-hash.mjs`에 반과 낱말을 넣어 나온 줄을 `config.js`에 붙인다. 도구는 낱말을 파일에 남기지 않는다.

## 5. 잠긴 파일과 학교 계정 입구

### 5.1 접속 경로

```
학생이 입구 주소를 엶 ─ 학교 계정 ─→ 입구 화면 "입장" ─→ 웹앱 주소#k=열쇠 ─→ 웹앱이 잠긴 파일을 풂
                      └ 학교 계정 아님 → Google이 입구에서 막음
웹앱 주소로 바로 옴 → 열쇠 없음 → S0 권한 없음 문구
```

### 5.2 잠그는 방법

- 알고리즘: AES-GCM 256비트. 브라우저는 Web Crypto, 도구는 Node의 같은 API를 쓴다. 외부 라이브러리 없음.
- 열쇠: 무작위 32바이트를 base64url 글자로 쓴 것. `tools/lock.mjs`가 처음 실행될 때 만들어 `private/vault.key`에 둔다. 열쇠의 내용은 저장소, 코드, 보고, 로그, 커밋 메시지, 이 문서 어디에도 적지 않는다. `.gitignore`의 `private/`와 `*.key`가 막는다.
- 도구가 `private/`에 새로 만들 수 있는 파일은 `private/content/extras.json`과 `private/vault.key` 둘뿐이다. 교사가 둔 파일은 읽기만 한다.
- 파일 하나의 모양: `IV 12바이트 + 암호문 + 인증 꼬리 16바이트`. 파일 이름을 추가 인증 값으로 넣어, 파일을 서로 바꿔치기하면 풀리지 않는다.
- IV는 열쇠와 파일 이름과 평문 해시에서 만든다. 내용이 같으면 잠긴 파일도 같아서, 다시 잠가도 바뀌지 않은 파일은 커밋에 잡히지 않는다.
- 음성 묶음(`s{n}.bin`)을 풀면: `머리 길이 4바이트 + 머리 JSON({ id, 시작, 길이 } 목록) + mp3 바이트들`. 장면 1 묶음에는 뉴스 N1, 장면 6 묶음에는 N2가 함께 든다. 반복 파일 10개는 넣지 않는다.
- 크기: 음성 원본은 장면별로 0.7~1.9MB, 합쳐 약 7MB에 뉴스 0.9MB. 잠가도 크기는 거의 같다.
- `content/index.json`: `{ "v": "판 번호", "files": ["story.bin", "s1.bin", …] }`. 앱은 판 번호를 주소 뒤에 붙여 받아, 다시 잠근 뒤에 옛 파일이 남지 않게 한다.

### 5.3 만드는 흐름 (교사 컴퓨터)

```
private/audio_map.json ─┐
private/word_gloss.csv ─┤
private/content/extras.json ─┼─ node tools/check-content.mjs ─ 통과 ─→ node tools/lock.mjs ─→ content/*.bin, index.json
private/Reading, news ─┘                                              (private/vault.key를 읽거나 만든다)
커밋 전: node tools/check-repo.mjs  +  git status
```

- `check-content.mjs`가 보는 것: 덩어리 111개와 파일이 모두 있는지, 반복 파일이 섞이지 않았는지, 핵심 문장 16개·단어 30개·확인 문제 5개·카드 6장·간판 낱말 7개가 본문과 맞는지, 단어마다 실린 장면에서 한 번 이상 찾아지는지, 근거 줄과 카드 뒷면 문장이 실제 본문 안에 있는지.
- `check-repo.mjs`가 보는 것: 커밋 대상에 `.mp3`, `private/`, 열쇠 글자, 본문 문장(평문 본문에서 뽑은 문장이 저장소 파일에 그대로 있는지), 장면 5 암호 낱말이 없는지.
- 도구는 열쇠와 암호를 화면에 찍지 않는다.
- `private/`의 자료를 고친 뒤에는 `check-content.mjs` → `lock.mjs`를 다시 실행하면 된다. 내용이 바뀐 잠긴 파일만 새로 쓰이고 판 번호가 바뀐다.
- 확인 문제 선지와 카드 뒷면의 곧은 따옴표(')는 잠글 때 본문과 같은 둥근 따옴표(’)로 바꾼다.
- 잠금 시험: 로컬 서버에서 `tools/vault-test.html`을 연다. 이 페이지는 `private/vault.key`를 읽으므로 `.gitignore`에 넣어 커밋하지 않는다. 열쇠가 없을 때·틀릴 때 풀리지 않는지, 바른 열쇠로 `story.bin`과 음성 묶음 6개가 풀리는지, 주소창에서 열쇠가 지워지는지를 본다.

### 5.4 푸는 흐름 (학생 기기)

1. 입구가 `웹앱 주소#k=열쇠`로 넘겨 준다. `#` 뒤는 서버로 전송되지 않는다.
2. `vault.js`가 `#k=`를 읽어 `tt8:key`에 저장하고 곧바로 주소창에서 지운다(`history.replaceState`).
3. `story.bin`을 받아 풀어 본다. 풀리면 S0를 보여 주고, 열쇠가 없거나 풀리지 않으면 권한 없음 문구를 보여 준다.
4. 장면을 열 때 그 장면의 음성 묶음을 받아 풀고, 덩어리별로 소리 자료(AudioBuffer)로 바꿔 메모리에만 둔다. 다른 장면으로 가면 버린다.
5. 이어 듣기는 덩어리를 Web Audio로 시각을 맞춰 이어 붙여 끊김 없이 튼다. 문장 듣기는 그 줄의 덩어리만 이어 튼다.
6. 푼 내용은 기기에 저장하지 않는다. 음성에는 주소(`src`)가 생기지 않아 내려받을 대상이 없다.

그림과 영상(잠그지 않음)에는 오른쪽 누르기와 끌어서 저장하기를 막고, 영상에는 조작 막대와 내려받기 단추를 두지 않는다.

### 5.5 입구 Apps Script (apps-script/gate/Code.gs)

| 항목 | 내용 |
| --- | --- |
| 하는 일 | 하나뿐: 열쇠를 붙여 웹앱 주소로 넘겨 준다 |
| 화면 | \[본부\] "신원 확인 완료." 단추 "입장". 누르면 웹앱 S0으로 간다. 자동으로 넘기지 않는다 |
| 열쇠·웹앱 주소 | 스크립트 속성(Script Properties)에만 둔다. 저장소의 코드에는 없다 |
| 배포 | 웹 앱, 실행: 나, 액세스: 학교 도메인 내 모든 사용자 |
| 학교 계정이 아닐 때 | Google이 로그인 또는 접근 거부 화면을 보여 준다. 웹앱까지 오지 못한다 |
| 모으는 것 | 없음. 누가 열었는지 적지 않는다 |
| 결과 수신과의 관계 | 서로 다른 웹 앱. 결과 수신은 열쇠를 모른다 |

학생이 누르는 단추는 두 번이다: 입구의 "입장", S0의 "접속"(영상 소리를 켜는 누름).

열쇠를 바꿀 때: `private/vault.key`를 지우고 `lock.mjs`를 다시 실행 → `content/`를 커밋·푸시 → 입구의 스크립트 속성을 새 열쇠로 바꿈. 학생 기기의 옛 열쇠는 풀리지 않게 되어 입구로 다시 들어와야 한다.

### 5.6 이 구조가 막지 못하는 것

- 학교 계정으로 들어온 학생의 기기에는 열쇠가 있다. 그 학생이 마음먹으면 본문과 음성을 꺼낼 수 있다.
- 입구가 넘겨 준 주소가 브라우저 방문 기록에 남을 수 있다.
- 장면 5 암호는 짧은 낱말이라, 해시를 보고 낱말을 하나씩 넣어 맞춰 보는 것까지는 막지 못한다. 저장소를 열어 보는 것만으로 암호가 보이지 않게 하는 장치다.
- 접근 제한·복제 방지·경고 문구를 갖추는 설계이고, 법적으로 충분한지는 스토리보드 10장대로 출판사나 한국저작권위원회에 확인한다.
