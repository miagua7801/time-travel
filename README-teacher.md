# 교사용 설명서 — Lesson 8 읽기 중 활동 웹앱

중2 영어 Lesson 8 *A Butterfly That Changed the Future*의 읽기 중 활동 웹앱을 수업에 쓰기까지의 순서입니다.
설계는 `docs/ARCHITECTURE.md`, 화면과 문구는 교사 컴퓨터의 `private/스토리보드.md`를 따릅니다.

전체 흐름은 이렇습니다.

```
private 자료 놓기 → 잠그기 → 커밋·푸시(GitHub Pages) → 입구 배포 → 결과 수신 배포 → config.js 설정 → 수업 전 확인 → 수업 → 단원이 끝난 뒤
```

## 0. 지킬 것

- **교과서 본문, 단어 뜻, 출판사 음성, 뉴스 N1·N2는 `private/`에만 평문으로 둡니다.** 저장소에는 잠긴 파일(`content/`)만 올라갑니다. `private/`는 `.gitignore`가 막습니다.
- **열쇠(`private/vault.key`)는 교사 컴퓨터와 입구 Apps Script의 스크립트 속성 두 곳에만 둡니다.** 메신저, 문서, 저장소, 커밋 메시지에 붙여 넣지 않습니다.
- 학생에게는 **입구 주소만** 알립니다. 웹앱 주소(`github.io`)는 알리지 않습니다.
- 학생 정보는 반·번호뿐입니다. 이름·이메일·기기 정보는 모으지 않습니다.
- 모든 화면 아래에 "수업 목적 자료. 수업 외 복제·배포 금지. 출처: 동아출판 중학교 영어 2(윤정미)"가 나옵니다.

필요한 것: 교사 컴퓨터에 [Node.js](https://nodejs.org) 20 이상, Git, 학교 Google 계정.

## 1. private 자료 놓기

저장소 폴더 안에 `private/` 폴더를 두고 아래 파일을 넣습니다. 이 폴더는 커밋되지 않습니다.

| 파일 | 내용 |
| --- | --- |
| `private/스토리보드.md`, `private/기획안.md` | 화면·문구의 기준 문서 |
| `private/audio_map.json` (`.csv`) | 음성 파일과 본문 문장의 짝 (교사 확인 완료) |
| `private/word_gloss.csv` | 단어 뜻 30개 |
| `private/content/extras.json` | 핵심 문장 번호, 확인 문제, 카드 뒷면, 간판, 인용 |
| `private/Reading/R_*.mp3` | 출판사 본문 음성 121개 (반복 파일 10개는 쓰지 않음) |
| `private/news/news_N1.mp3`, `news_N2.mp3` | 장면 1·6의 TV 뉴스 |

## 2. 잠그기

저장소 폴더에서 터미널을 열고 차례로 실행합니다.

```bash
node tools/check-content.mjs
```

```bash
node tools/lock.mjs
```

- `check-content`는 자료끼리 맞는지만 봅니다. "오류"가 나오면 그 줄을 고친 뒤 다시 실행합니다. 교과서 문장은 화면에 찍지 않고 학습지 D 번호와 파일 이름으로 알려 줍니다.
- `lock`은 `content/`에 잠긴 파일(`story.bin`, `s1.bin` ~ `s6.bin`, `index.json`)을 만듭니다. 처음 실행하면 `private/vault.key`(열쇠)도 만듭니다. 이 파일은 지우지 말고 백업해 둡니다. 잃어버리면 4번의 "열쇠 바꾸기"를 해야 합니다.
- `private/` 자료를 고친 뒤에는 두 명령을 다시 실행하면 됩니다. 내용이 바뀐 파일만 새로 쓰입니다.

잠근 뒤에는 커밋 전 점검을 하고 GitHub에 올립니다.

```bash
node tools/check-repo.mjs
```

`점검 통과`가 나오고 `git status`에 `private/`나 `.mp3`가 없으면 커밋·푸시합니다. GitHub Pages가 켜져 있으면 1~2분 뒤 웹앱 주소(예: `https://<계정>.github.io/time-travel/`)에 반영됩니다.

## 3. 입구 배포 (학교 계정 확인)

학교 계정으로 들어온 학생에게만 열쇠를 넘겨 주는 Apps Script 웹 앱입니다. 자세한 화면 순서와 문제 해결은 `apps-script/README.md`의 "입구 배포"에 있습니다.

1. 학교 계정으로 script.google.com → **새 프로젝트** → `apps-script/gate/Code.gs`를 통째로 붙여 넣기.
2. **프로젝트 설정 → 스크립트 속성**에 `KEY`(= `private/vault.key`의 한 줄 43자), `APP_URL`(= 웹앱 주소, 끝에 `/`).
3. **배포 → 새 배포 → 웹 앱**, 실행: **나**, 액세스: **(학교) 내 모든 사용자**.
4. 나온 웹 앱 주소(…`/exec`)가 **입구 주소**입니다. 학생에게는 이 주소만 알립니다.

입구 주소는 `data/config.js`의 `GATE_URL`에 넣지 않고 빈 값으로 둡니다. 저장소가 공개라서 누구나 볼 수 있기 때문입니다. 교사 메모장 등 따로 적어 둡니다.

열쇠가 맞는지는 `node tools/key-check.mjs`(교사 컴퓨터)와 입구 편집기의 `checkKey` 실행 로그의 **열쇠 지문 8자**를 견주어 확인합니다. 열쇠 자체는 어디에도 찍지 않습니다.

## 4. 결과 수신 배포와 config.js 주소 넣기

학생 기기가 보낸 결과를 반별 시트(2-1 ~ 2-6)에 한 학생 한 줄로 적는 Apps Script 웹 앱입니다. 입구와는 **다른 프로젝트**로 만듭니다. 순서는 `apps-script/README.md`의 "결과 수신 배포"에 있습니다.

1. 학교 계정 Google 드라이브에 새 스프레드시트를 만들고 **확장 프로그램 → Apps Script**에 `apps-script/results/Code.gs`를 통째로 붙여 넣습니다.
2. **배포 → 새 배포 → 웹 앱**, 실행: **나**, 액세스: **모든 사용자**. (학생 기기는 로그인 정보 없이 보내므로 '모든 사용자'여야 받습니다. 받는 것은 반 목록에 있는 반과 1~40번뿐입니다.)
3. 나온 주소(…`/exec`)를 브라우저로 열어 `ok`가 보이는지 확인합니다.
4. `data/config.js`의 `RESULT_URL`에 그 주소를 넣고 커밋·푸시합니다.

```js
export const RESULT_URL = 'https://script.google.com/macros/s/……/exec';
```

- `RESULT_URL`이 비어 있으면 결과를 보내지 않고 게임만 동작합니다. 결과는 학생 기기의 대기열에만 남습니다.
- 반 목록을 바꾸면 `data/config.js`의 `CLASSES`와 `Code.gs`의 `ALLOWED_CLASSES`를 **둘 다** 같게 고칩니다.
- 시트에는 단서 칸에 교과서 문장이 들어갑니다. **시트를 공개로 공유하지 않습니다.**

**결과 시트의 모양**

| 열 | 내용 |
| --- | --- |
| 번호 | 학생 번호 (번호 순으로 정렬) |
| 여행 | 첫 여행 / 두 번째 여행 |
| 마친 장면 | 0 ~ 6 |
| 확인1·2·4·5·6 | `O` = 첫 시도 정답, `X2` = 첫 시도 오답(고른 선지 번호) |
| 예측①②③ | 고른 선택지. 두 번째 여행은 "D21 문장 / 이유" 또는 "없다" |
| 관찰①②③ | excited 등 고른 그림 카드 |
| ★1·2·5·6 | ★ 도전에 쓴 답 (고쳐 내면 바뀜) |
| 간판 오답 | S9에서 틀린 횟수 |
| 엔딩 | 수료증까지 갔으면 `O` |
| 단서1~5 | "장면 번호 · D 번호 문장 / 메모" (S11 "보고" 뒤) |
| 받은 시각 | 마지막으로 받은 때 |

- **덮어쓰기는 칸 단위입니다.** 같은 반·번호가 다시 보내면 이번에 온 칸만 바뀌고 나머지는 그대로입니다. 기록이 사라진 기기에서 "장면 5부터"로 들어와도 1차시 칸은 지워지지 않습니다.
- 보내는 때: 장면을 마칠 때, S6, ★ 도전을 낼 때, S10 수료증, S11 "보고". 보내지 못하면 학생 화면에는 알리지 않고 기기에 남겨 두었다가 다음에 함께 보냅니다.

## 5. 반별 암호 해시 넣기

장면 5는 반마다 다른 낱말로 잠겨 있습니다. `data/config.js`에는 낱말이 아니라 **해시만** 둡니다.

```bash
node tools/code-hash.mjs 2-1 낱말 2-2 낱말 2-3 낱말 2-4 낱말 2-5 낱말 2-6 낱말
```

- 나온 여섯 줄을 `data/config.js`의 `CODE_HASHES` 안에 바꿔 붙이고 커밋·푸시합니다.
- 스토리보드 S8 표의 낱말을 그대로 쓰려면 `node tools/code-hash.mjs --storyboard`.
- 낱말은 영문 글자만, 대소문자는 구분하지 않습니다. 낱말은 2차시에 그 반에만 말해 줍니다. 낱말을 저장소, 칠판 사진, 단체방에 남기지 않습니다.

**수업 날**

- [ ] 1차시: 학생에게 입구 주소를 알린다. 영상 소리가 나므로 이어폰.

## 7. 단원이 끝난 뒤

- **복습용으로 남길 때:** 입구는 그대로 두고 `data/config.js`의 `RESULT_URL`만 비워 커밋·푸시합니다. 결과는 더 쌓이지 않습니다.
- **닫을 때:**
  1. 입구 Apps Script → **배포 → 배포 관리** → 입구 배포를 **보관처리**. 이제 새로 들어오는 학생은 열쇠를 받지 못합니다.
  2. 결과 수신 배포도 보관처리합니다. 결과 시트는 필요한 만큼 보관한 뒤 지웁니다.
  3. GitHub 저장소를 **비공개**로 돌립니다: Settings → General → 맨 아래 Danger Zone → Change repository visibility → Private. (무료 계정은 비공개 저장소의 Pages가 닫힙니다.)
- **열쇠 바꾸기** (열쇠가 새었거나 학생 기기의 열쇠를 모두 무효로 하고 싶을 때):
  1. `private/vault.key`를 지우고 `node tools/lock.mjs` → 새 열쇠와 새 잠긴 파일.
  2. `node tools/check-repo.mjs` → `content/`를 커밋·푸시.
  3. 입구 스크립트 속성 `KEY`를 새 열쇠로 바꿉니다(다시 배포하지 않아도 됨). `node tools/key-check.mjs`와 `checkKey`의 지문이 같은지 봅니다.
  4. 학생 기기의 옛 열쇠는 풀리지 않게 되어, 입구 주소로 다시 들어와야 합니다. 기기의 진행 기록은 그대로 남습니다.

## 8. 고칠 때 (Claude Code로)

- 작업 규칙은 `CLAUDE.md`, 구조는 `docs/ARCHITECTURE.md`에 있습니다. 화면 문구는 스토리보드에 있는 문장만 씁니다.
- 화면 점검: 로컬 서버(`python -m http.server 8765`)를 켜고 `node tools/shot.mjs`(전체) 또는 `node tools/shot.mjs step6` 등. 캡처는 `tools/shots/`에 생기고 커밋하지 않습니다. `tools/shot*.mjs`는 열쇠를 읽으므로 커밋하지 않습니다.
- 결과 수신 코드 점검: `node tools/test-results.mjs` (가짜 시트로 `Code.gs`를 돌림. Google에 보내지 않음). `Code.gs`를 고치면 Apps Script에 다시 붙여 넣고 **배포 관리 → 새 버전**으로 다시 배포합니다. 주소는 그대로입니다.
